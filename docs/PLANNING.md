## 产品边界
主机启动一个服务 → 显示局域网地址 → 玩家打开页面 → 创建/加入房间 → 自动游客昵称和空座 → 三人到齐由房主开始。
只做浏览器端，优先桌面浏览器；不开发原生客户端。不做账号、密码、验证码、第三方登录、互联网匹配、排行榜、云服务或复杂权限。
保留原稿全部核心战棋规则；不做迷雾、随机地图、AI玩家、科技树、额外内容。热座不是必交付项。
连接身份使用浏览器自动保存的随机席位凭据，玩家无需输入；仅防止误操作别人的席位并支持刷新恢复，不构成账号系统。
主机进程内保存房间；重启会丢失对局，须明示。暂不做数据库、云存档和持久恢复。
## 技术方向（规划选择，尚未安装验证）
TypeScript 单仓库；React + Vite 浏览器 UI；Node.js HTTP + WebSocket 单进程；纯函数规则模块；npm 锁文件；Vitest 规则/服务测试，Playwright 三浏览器上下文集成验证。
目录建议：apps/web、apps/server、packages/game、packages/protocol、docs。
生产时同一服务提供页面和 WebSocket，浏览器根据当前 location 连接，不写死 localhost。监听 0.0.0.0，可配置端口，启动输出实际局域网候选地址。首次装依赖可联网，安装构建后游玩不依赖外网/CDN。
服务端唯一裁定规则、当前玩家及状态版本，前端只提交动作和显示结果。拒绝越权、过期、重复及非法命令；动作串行提交并广播完整快照。回合制小地图先用完整快照，避免复杂增量同步。

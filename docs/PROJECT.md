# PROJECT

> 权威职责：说明“这个项目是什么、为什么做、做什么、不做什么”。由高阶 Planner 维护。

## Project Name

Hex Frontier（临时代号；发布前由人类确认原创中文名与英文名）。

本项目是一个采用经典六角地图、资源生产、玩家交易与路线建设机制的原创 Web 局域网桌游。规划文档会用“基础规则玩法”描述兼容目标，但产品界面、代码资产和宣传不得冒充或复制 CATAN 官方产品。

## Vision

让 3–4 位朋友只需在同一局域网内启动一台主机服务，便可分别使用桌面浏览器完成一整局公平、可恢复、无需账号的多人游戏。

服务端是唯一规则裁判；浏览器只展示玩家可见状态并提交意图。即使刷新页面或短暂掉线，玩家也能凭本机重连凭据回到原座位。

## Users

- 在家庭、宿舍或聚会局域网内游玩的 3–4 位朋友；
- 负责启动服务、创建房间和处理局域网地址的房主；
- 后续维护规则、客户端和联机能力的开发者与 AI Executor。

## Goals

- [ ] 支持 3 人和 4 人创建、加入、准备并开始游戏。
- [ ] 支持固定平衡地图与带种子的合法随机地图。
- [ ] 完整覆盖本项目定义的基础规则闭环：初始放置、掷骰与生产、玩家/银行/港口交易、道路/聚落/城市建造、强盗与弃牌、发展卡、最长道路、最大骑士、10 分胜利。
- [ ] 所有随机结果与规则合法性均由权威服务端决定。
- [ ] 支持浏览器刷新、网络瞬断后的身份恢复与状态追平。
- [ ] 使用原创名称、图标、配色、图形和占位视觉，不复制官方美术、版式、文案或品牌素材。
- [ ] 通过自动化规则测试和 3–4 浏览器端到端测试证明核心流程可用。

## MVP User Journey

1. 房主在一台局域网设备上启动服务，并看到可分享的本机访问地址。
2. 房主创建房间，选择 3/4 人、固定地图或随机地图；随机地图显示种子。
3. 朋友通过浏览器输入局域网地址，以昵称加入；每个座位获得仅保存在该浏览器的重连凭据。
4. 所有人准备后，服务端锁定座位、生成地图和顺序，按蛇形顺序完成两轮初始聚落与道路放置。
5. 玩家轮流掷骰、处理生产或 7 点事件、交易、建造、购买/使用发展卡并结束回合。
6. 服务端持续计算最长道路、最大骑士与隐藏/公开胜利点，在当前玩家自己的回合达到 10 分时结束游戏。
7. 玩家刷新或短暂离线后可恢复座位，获得最新公开状态和仅属于自己的私密手牌。
8. 游戏结束页显示胜者、公开得分构成和可审计的公开事件摘要。

## Core Requirements

### Multiplayer and LAN

- 单房间仅允许 3 或 4 个玩家座位；MVP 可同时承载多个独立房间。
- 服务监听可配置地址，局域网模式默认允许绑定 0.0.0.0；启动输出不得把 localhost 误当作其他设备可访问地址。
- 无云端账号、无公网匹配。房间码加玩家重连令牌构成轻量身份机制。
- 重复、乱序或过期命令必须幂等处理或明确拒绝，不能重复扣资源/建造。
- 玩家断线不自动跳过回合；房间显示连接状态，重连后继续。房主可在一致同意下终止房间，但 MVP 不实现踢人或代打。

### Authoritative Rules

- 客户端不得决定骰子、随机偷取、抽发展卡、地图洗牌、资源结算、合法位置、奖项或胜负。
- 服务端以命令前置条件、房间修订号和状态机校验每次动作。
- 公开事件不泄露他人的资源种类、未使用发展卡内容、重连令牌或发展牌堆顺序。
- 规则结果必须可由确定性测试重放；随机源通过显式种子或可注入接口进入领域层。

### Maps

- 固定地图：提供一份仓库内原创呈现、坐标明确、平衡的基准布局。
- 随机地图：维持基础组件数量，沙漠不放数字；默认不让高概率数字 6 与 8 相邻；同一种子产生同一布局。
- 两种地图都使用同一拓扑、建造、港口和规则引擎。

### Ruleset Boundary

- 仅支持 3–4 人基础玩法，不包含 2 人变体、5–6 人扩展、航海/城市与骑士等扩展。
- 初始放置为正序一轮、反序一轮；第二个聚落结算相邻起始资源。
- 7 点事件按“手牌超过 7 的玩家弃一半（向下取整）→ 全部完成后移动强盗 → 选择合法目标并随机偷取”执行。
- 当前玩家行动阶段可交错交易与建造；玩家间交易必须有双向资源交换，不允许赠送、赊账或非资源承诺。
- 胜利目标为 10 分，且只在该玩家自己的回合确认；隐藏胜利点计入实际得分。
- 详细不变量以 ARCHITECTURE.md 和规则测试为准。

## Non-Goals

MVP 明确不做：

- 公网托管、云存档、账号系统、好友系统或全球匹配；
- 2 人、5–6 人、观战、机器人玩家、锦标赛和扩展规则；
- 移动端原生应用或手机优先布局；
- 文本/语音聊天、回放播放器、排行榜或数据分析；
- 针对恶意公网攻击者的完整反作弊；局域网内仍做输入校验、秘密隔离和基本限流；
- 复制官方棋盘插画、卡牌画面、字体、图标、规则书文字、商标 Logo、音效或宣传版式；
- 对官方产品名称、兼容性或授权关系作暗示。

## Constraints

- 一台普通个人电脑可作为主机，不依赖外部数据库或第三方云服务。
- 首选单仓库 TypeScript 技术栈；具体决策见 ADR-002。
- 领域规则必须与网络、UI 和存储解耦，可在无浏览器、无 Socket 的情况下测试。
- 任何私密状态都必须经玩家视图投影后才可发送。
- 首版界面面向现代桌面浏览器，键盘与颜色以外的状态提示不可缺失。
- 服务异常重启的恢复能力通过本地版本化快照实现；敏感令牌不写入公开日志。
- 仓库不得引入来源不明或许可不兼容的图像、字体、音频和规则文本。

## Success Criteria

MVP 只有同时满足以下结果才算完成：

1. 三个浏览器与四个浏览器两种场景都能从大厅完成一局到 10 分胜利。
2. 固定地图在所有客户端一致；给定随机种子在服务端和测试中稳定复现。
3. 覆盖所有 Core Requirements 的领域测试通过，包含非法动作与边界情况。
4. 任意非当前玩家动作、资源不足、非法建造、过期修订号和重复 commandId 均不会改变状态。
5. 对手网络响应和日志中不出现自己的私密牌面之外的信息。
6. 在服务器仍运行时，玩家刷新或断网后使用原浏览器可恢复同一座位、手牌与可行动状态；服务器重启后可从最近的有效快照恢复未结束房间。
7. 3–4 客户端局域网手工验收无阻断级问题，且关键路径有 Playwright 多上下文自动化覆盖。
8. 用户可按 README 在干净环境完成安装、启动、创建和加入房间。
9. 视觉与文案审查确认无官方品牌、美术或大段规则文本复制，第三方资产均有许可记录。

## Product Decisions Already Made

- 局域网优先、无账号。
- 3–4 人基础规则是 MVP 的唯一规则集。
- 服务端权威，客户端不保存可裁决的真实游戏状态。
- 房主选择固定或随机地图；随机地图提供种子。
- 临时掉线不会自动托管或跳过玩家。
- 原创占位视觉优先于任何官方素材。

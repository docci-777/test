# ADR-003 — 原创产品身份、视觉资产与规则表达边界

**Status:** ACCEPTED  
**Date:** 2026-09-03  
**Decision Owners:** 高阶 Planner  
**Related Tasks:** TASK-008, TASK-011, TASK-012  
**Supersedes:** None  
**Superseded By:** None

## Context

项目目标是实现相近的基础规则体验，但官方名称、Logo、棋盘/卡牌插画、图标、字体、音效、版式和规则书文字可能受商标、版权或许可约束。仓库是公开的，任何临时素材都可能被误认为可发布资产。

## Decision

1. 使用原创临时代号 Hex Frontier，正式名称发布前由人类确认；产品界面不以 CATAN、卡坦岛或近似商标作为应用名。
2. 所有棋盘地形、资源、建筑、卡牌背面、奖项、Logo、音效与界面布局均原创制作，首版优先使用简单几何 SVG、CSS 与文字占位。
3. 不导入、描摹、截图、裁切或风格复刻官方实物/数字产品素材。
4. 不复制规则书的大段文字或图示；仓库规则说明用自己的结构和措辞概括可操作事实，并链接合法公开参考。
5. 第三方字体、图标、声音或图像必须进入 assets/original/NOTICE.md，记录来源、作者、许可证和用途；不明确即不用。
6. 代码内部可以使用通用机制术语和中性资源枚举；面向用户的名称、图形与品牌叙事保持原创。
7. README/关于页在需要时用事实性说明表达“非官方、无隶属或授权关系”，不得暗示兼容认证。
8. 发布审查由 TASK-012 执行；发现来源不明资产视为阻断问题。

## Rationale

- 简单几何视觉足以验证可玩性，不需要承担复制素材的风险。
- 从第一天隔离资产来源比发布前替换整套素材成本低。
- 自己撰写规则摘要既能指导实现，又避免把官方规则书当仓库内容复制。
- 中性领域术语让未来改名或主题替换不影响规则引擎。

## Alternatives Considered

### Option A — 直接使用网络搜索到的官方或粉丝素材作占位

- 优点：视觉完成度高、开发快。
- 缺点：来源与授权不清，临时素材极易进入发布版本。
- 未选择原因：与公开仓库和原创要求直接冲突。

### Option B — 完全无视觉，仅用文本表格

- 优点：法律和实现风险最低。
- 缺点：难以验证六角棋盘交互和多人可玩性。
- 未选择原因：原创 SVG/CSS 占位能以很低成本支持真实交互。

### Option C — 使用通用开源图标库但不登记

- 优点：开发方便。
- 缺点：许可证、署名和再分发要求容易丢失。
- 未选择原因：允许使用，但必须经过许可清单。

## Consequences

### Positive

- 降低公开仓库和后续分发的知识产权风险。
- 视觉主题可独立演进，不污染领域代码。
- 每项外部资产都有可追溯许可。

### Negative / Trade-offs

- 首版观感更像功能原型。
- 需要额外设计原创图形和文案。
- 事实性规则兼容与品牌表达必须持续人工审查。

### Follow-up

- TASK-008 仅使用原创 SVG/CSS/文字占位实现 UI。
- TASK-011 在 README/关于页加入准确的非官方说明和资产运行要求。
- TASK-012 完成仓库扫描、许可清单、可访问性与视觉发布审查。

## Validation / Revisit Trigger

- 正式商业发布、应用商店上架或宣传投放前必须重新进行专业法律/品牌审查。
- 若获得明确授权，另建 ADR 记录范围；在此之前本决策持续有效。
- 若用户要求加入某项外部素材，必须先确认许可并更新 NOTICE。

# Game Rules Contract

本文件是实现与测试的规则事实来源。描述必须使用项目自己的语言，不复制商业规则书原文。

## 规则范围

- 采用 3–4 人标准基础玩法作为首版口径。
- 不实现扩展、变体或可选家规。
- 若实际桌游版本存在差异，必须通过 ADR 明确选择后再编码。

## 回合状态机

计划中的主要阶段：

1. `setup-forward`：按顺序放置第一组建筑与道路。
2. `setup-reverse`：逆序放置第二组建筑与道路并领取初始资源。
3. `turn-start`：当前玩家回合开始。
4. `roll-required`：必须掷骰或使用允许的骰前行动。
5. `discard-required`：掷出 7 后，满足条件的玩家弃牌。
6. `robber-move-required`：移动强盗并在合法时选择受害者。
7. `action`：交易、建造、购买或使用允许的发展牌。
8. `turn-end`：结算并转交回合。
9. `finished`：达到胜利条件，拒绝后续玩法命令。

具体允许命令应在对应 Issue 中定义；未定义前不得假设阶段可跳过。

## 必须覆盖的规则域

- 棋盘：地块、数字标记、港口、顶点、边及邻接关系
- 玩家：手牌、建筑库存、道路、发展牌、公开奖励与分数
- 银行：资源和发展牌库存
- 建造：道路、定居点、城市的连接、距离、库存与费用
- 生产：骰点、地块、强盗阻断、相邻建筑倍率和银行不足
- 强盗：弃牌、移动限制、合法受害者及随机抽取
- 交易：银行、港口与玩家报价的合法性和原子性
- 发展牌：购买回合限制、每回合使用限制和各牌效果
- 奖励：最长道路、最大骑士力、并列与失去资格
- 胜利：分数来源、检查时机和游戏终止

## 已确定的不变量

- 失败命令不得改变任何游戏状态。
- 所有资源数量、库存数量和建筑数量均不得为负数。
- 一条边最多存在一条道路，一个顶点最多存在一个建筑。
- 强盗始终位于一个合法地块。
- 当前玩家与阶段必须共同决定允许的命令集合。
- 隐藏信息不得出现在面向其他玩家的事件中。

## 编码前仍需拆分确认的复杂边界

- 最长道路在分叉、闭环、对手建筑阻断与并列时的精确算法
- 银行资源不足时，多名玩家同时生产的分配口径
- 多个玩家可被强盗掠夺时的选择流程
- 发展牌购买与使用的回合限制
- 胜利条件的检查时机

这些边界必须由专门 Issue 给出示例和验收标准后实现。
